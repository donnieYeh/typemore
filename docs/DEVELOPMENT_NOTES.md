# Typemore 开发记录

## 项目定位

Typemore 以 `Windows-only` 首版为目标，重点解决“快速语音输入到任意前台应用”的桌面体验问题。

## 关键实现决策

### 1. 桌面壳

- 使用 `Tauri v2`
- 前端为 `React + Vite`
- 后端为 `Rust`

选择原因：

- Windows 桌面能力够用
- 打包链路成熟
- Rust 后端适合接音频、输入模拟、窗口控制和系统交互

### 2. 本地转写

- 使用 `whisper.cpp` 官方 CLI
- 不直接把 Whisper 绑定进 Rust 进程

这样做的好处是：

- 降低模型接入复杂度
- 更容易替换模型或 CLI 版本
- Windows 分发更稳

### 3. 热键策略

最初尝试过 Tauri 的 `global-shortcut` 插件，但“单独 Alt”不适合作为标准快捷键注册。

最终方案：

- 只监听 `右 Alt`
- 改为轮询按键状态
- 引入可配置缓冲时间，避免抖动和连按误切换

### 4. 输出策略

自动投递优先，剪贴板兜底。

现有逻辑：

- 优先尝试向第三方前台窗口 `Ctrl+V`
- 如果不适合或失败，则写入剪贴板
- 保证结果不会丢

### 5. 悬浮窗

使用单独 `overlay` 窗口而不是在主窗口里做浮层。

原因：

- 不依赖主窗口是否显示
- 更接近系统级录音浮层体验
- 容易做透明、置顶、无任务栏显示

## 经验总结

### 1. 托盘交互不能只依赖 `show()`

如果主窗口被真正关闭，托盘点击时必须支持：

- 窗口隐藏恢复
- 最小化恢复
- 必要时窗口重建

### 2. 关闭主窗口更适合“隐藏到托盘”

桌面常驻工具不应把关闭按钮等同于退出。

### 3. 短文本不要过度调用大模型

很短的转写结果直接输出更稳，也更快。

### 4. 文本后处理比 ASR 本身更影响可用性

用户真实感知往往不在“字是否完全对”，而在：

- 是否流畅
- 是否去掉口头卡顿
- 是否便于直接发送

## 后续可继续优化的方向

- 更细的麦克风设备选择
- 本地模型切换
- 多语言模式
- DeepSeek prompt 风格切换
- 录音能量条或更拟真的悬浮动效
- 打包成正式 MSI 安装器并自动下载资源
